# 坦克大战：全息军械库 — 设计文档

- 日期：2026-10-31
- 状态：待批准
- 类型：本地同屏双人合作坦克防守游戏（pygame）

## 1. 意图与为什么

用 pygame 做一款两个人坐在同一台电脑前、共用键盘合作的坦克防守游戏。玩家各操作一台定位不同的坦克，在程序生成的网格迷宫里抵御敌人、保护基地，推进 8 个关卡并在关间选择升级。

想要的核心体验：经典坦克大战的守家压力 + 程序生成带来的每局新鲜感 + 未来科技美术 + 两台坦克真正不同的技能分工。不是原版复刻，而是借这个题材做一款更现代的双人合作小游戏。

一局目标时长 20-30 分钟。

## 2. 目标

- 同键盘双人，即开即玩，不需要手柄或联网。
- 程序生成、可破坏、保证连通且有多条进攻路线的网格迷宫。
- 两台坦克定位明确：P1 手榴弹负责范围清群，P2 激光负责直线高伤/穿透。
- 基地防守与主动清场之间形成真实取舍，鼓励分兵。
- 8 关结构：3 普通 → 精英 1 → 3 普通 → 精英 2 → 最终 Boss。
- 关间两人各自三选一升级，形成不同流派。
- 未来科技视觉：全息军械库（钢蓝灰、白色全息描边、冷蓝/琥珀双色）。
- 纯 pygame，无外部图片/音频素材依赖。

## 3. 非目标

- 在线或局域网联机。
- 手柄、手机、触屏支持。
- 关卡编辑器或地图分享。
- 剧情、过场动画、配音。
- 中途存档/续关（最高分或最远关卡记录可选，非首版必须）。
- 外部美术素材管线、精灵图导入流程。

## 4. 反目标（即使能跑也算失败）

- 两台坦克只是换色，技能不影响打法或站位。
- 生成的关卡经常堵死、基地无路可走，或只有一条固定路线。
- 守家变成必须一直蹲家，玩家没有主动清场的空间。
- 轻微误伤变成频繁互相坑死，挫败感大于合作乐趣。
- 画面太暗或太吵，看不清弹道、敌人、基地状态和冷却。
- 8 关内容重复，精英和 Boss 只是血更厚。
- 双人操作键位冲突或需要看文档才能上手。

## 5. 约束

- Python 3 + pygame（可用 pygame-ce，但按 pygame API 写）。
- 单机、同一键盘、无网络。
- 目标 60 FPS，默认窗口 1280x720（可调）。
- 所有图形用 pygame 绘制；辉光用加色混合（BLEND_ADD）与多层半透明实现。
- 逻辑与渲染分离，纯逻辑部分可用 pytest 测试。
- 代码按模块拆分，数值集中在配置表（Python 常量/dataclass），不散落在各处。

## 6. 已定玩法

### 6.1 一局的结构

3 个普通关 → 精英关 1 → 3 个普通关 → 精英关 2 → 最终 Boss。共 8 关。

关卡结束条件：

- 普通关：每关有固定敌人配额（随关卡递增）；配额全部刷出并被消灭后过关。
- 精英关：击败精英小怪，并清光剩余敌人后过关。
- 最终 Boss 关：击败 Boss 即通关。

- 失败：基地 HP 归零。玩家被击毁后会无限次复活，两人同时阵亡不会结束本局。
- 胜利：击败最终 Boss。
- 关间：两名玩家各自从 3 张随机升级中选 1 张，然后进入下一关。
- 失败后整局重来，不保留升级。

### 6.2 玩家与技能

- 移动：四方向移动，转向即改变朝向；网格/瓦片碰撞，不斜向移动。
- 普通射击：有射速限制，无独立冷却条。
- P1 手榴弹：向当前朝向抛出，落点范围爆炸；范围伤害，可破坏砖墙，不破坏钢墙；冷却较长；对队友和自己有轻微伤害（约为对敌伤害的 35%）。
- P2 激光：瞬间直线光束，高伤，可穿透多个敌人；被钢墙挡住，击中砖墙则破坏该格并停止；不伤队友。
- 技能各有独立冷却，HUD 显示；冷却期间不可释放。
- 玩家坦克有 3 点 HP（护甲类升级可提高上限或减伤），受击后有 0.5 秒无敌帧；HP 归零才算被击毁。
- 被击毁：3 秒后在基地附近重生，2 秒无敌；复活次数无限。

误伤矩阵（评审后由 builder 定为默认，人类可推翻）：

- 普通子弹：不伤害队友，不伤害基地。
- 手榴弹：对队友和自己造成 35% 伤害；不伤害基地。
- 激光：穿过队友且不造成伤害；不伤害基地。
- 敌方子弹和敌方爆炸：正常伤害玩家与基地。

### 6.3 基地

- 基地位于迷宫底部中央，占 2x2 格。
- 基地有 4 点 HP（比原版一击毁更宽容），外观和 HUD 显示当前状态；护盾类升级可吸收额外伤害。
- 敌人寻路优先目标为基地；部分敌人优先追击玩家。
- 基地 HP 归零立即失败。
- 每关开始时基地 HP 重置为 4（护盾升级提供本关内的额外吸收），不跨关累积伤害。

### 6.4 敌人

基础三种：

- 追踪者（Tracker）：直奔基地，速度中等，近距离射击；数量主力。
- 炮手（Gunner）：保持距离、远程压制玩家，移动较慢，会绕到有射击线的位置。
- 爆破者（Demolisher）：优先拆砖墙开路，靠近基地或玩家后自爆/高伤近战；能打开新路径。

精英关：

- 在普通敌人组合之外，额外出现 1 个会主动使用技能的精英小怪（例如护盾、召唤、激光），有独立血条和明显前摇。
- 精英小怪是精英关的额外压力点，不替代普通敌人。
- 高速精英 X：第 1-7 关在普通精英之外额外出现 1 只，保留护盾和召唤，但只发射单发弹；移动速度为普通炮手的 2 倍。

最终 Boss：

- 多阶段，围绕基地攻击；阶段切换有明确提示。
- 至少 3 个阶段，攻击要有可学习的前摇，不能纯靠反应不及。
- 具体弹幕与技能模式由 builder 设计。

### 6.5 关卡生成（A 网格迷宫）

- 网格约 24x13 格（tile 48），四周为钢墙边界，基地在底部中央。
- 砖墙可破坏，钢墙不可破坏。
- 墙体与弹道规则（评审后由 builder 定为默认，人类可推翻）：
  - 普通子弹（双方）命中砖墙会破坏该格并消失；命中钢墙消失。
  - 手榴弹走抛物线，越过墙体落在目标点，不需要视线；爆炸破坏范围内砖墙，不破坏钢墙。
  - 激光被钢墙挡住，命中第一格砖墙时破坏该格并停止，不穿透砖墙。
- 生成必须保证：
  - 顶部 2-3 个出生点到基地至少有 3 条路线。验收定义（builder 默认）：把砖墙视为可通行、钢墙视为阻挡，从所有出生点集合到基地至少存在 3 条互不共享超过 30% 格子的路线；每个出生点至少各有 1 条路线。砖墙被破坏后路线只会变多，不会变少。
  - 基地不会被钢墙完全封死；至少保留 2 个朝向不同的入口方向。
  - 出生点周围有安全区，避免一出生就被堵。
  - 砖墙/钢墙比例可配置。
  - 每次战斗在基地正前方 2 格、基地两列中随机一列生成 1 个钢块；它参与路线校验，不可破坏。
- 生成后用 BFS/A* 校验连通与路线数；不满足则重生成，设置重试上限并保留一个手工兜底模板。
- 敌人寻路使用 A* 或流场；砖墙被破坏后重新计算路径。
- 难度随关卡提升：敌人数量、刷新频率、兵种比例、精英词缀。

### 6.6 升级

- 每关结束，两名玩家各自从 3 张随机升级中选 1 张。
- 升级池覆盖：技能冷却、技能伤害/范围、普通弹伤害/射速、移动速度、护甲、基地护盾、特殊词缀（如手榴弹分裂、激光折射）。
- 同一升级可重复获取并叠层，设置上限。
- 反应装甲：每 20 秒获得 1 秒无敌；每次选择使间隔缩短 2 秒，最低 4 秒，最多 9 层。
- 两人独立成长，允许不同流派；升级选择不共享、不争夺。
- 展示方式（builder 默认）：同一屏幕先由 P1 选，再由 P2 选，无计时；另一人可以看到对方的选择。两名玩家每关都参与选择。

### 6.7 视觉方向（B 全息军械库）

- 深蓝灰背景，低对比冷色网格地面；墙体为钢蓝灰，白色全息描边。
- P1 冷蓝，P2 琥珀；敌方用红/橙警示色区分。
- 技能与弹道是画面中最亮的元素：手榴弹抛物线、落点范围预警、爆炸粒子；激光为白蓝光束加辉光，命中时轻微屏幕震动。
- HUD 位于底部：两人血条/复活状态、技能冷却条、基地 HP、关卡进度。
- 命中反馈：闪白、击退、粒子；音效可选。
- 全部图形程序化绘制，不依赖图片素材。

### 6.8 操作（默认，可改）

- P1：WASD 移动，Space 射击，F 手榴弹。
- P2：方向键移动，`.` 射击，`/` 激光。
- Esc 暂停，Enter 确认。
- 键位映射集中配置，方便修改。

### 6.9 界面流程

标题 → 操作说明 → 游戏 → 关间升级 → 下一关 → … → 失败/胜利 → 重开。

暂停时显示覆盖层，游戏逻辑暂停。

## 7. 方案（Approaches）

考虑过三种做法：

- **A. 纯 pygame 手写，按模块拆** — 自己写网格碰撞、敌人寻路、关卡生成、状态机；数值放 Python 配置表；美术全部程序化绘制。依赖最少、可控、体量匹配。
- **B. 数据驱动 + 调试面板** — 同样纯 pygame，但数值、关卡模板、升级池放 JSON，并做运行中调参面板。平衡迭代快，但第一版多一层加载校验和面板开发。
- **C. arcade / pygame-ce + ECS** — 用现成引擎的精灵、相机、物理，少写底层；但引入依赖、需要适应框架，全息辉光仍需自写。

**已选 A**，理由：8 关、3 兵种、2 场精英、1 个 Boss 的体量用纯 pygame 足够；依赖最少，本地运行简单；数值先写在配置表里，以后真想调参再加 JSON 也不迟。B 的首版成本不划算，C 的框架收益不足以抵消依赖与学习成本。

## 8. 架构（选 A 后）

建议模块：

- `main.py` — 启动、主循环、状态机入口
- `config.py` — 常量与数值表
- `game/states.py` — 标题、游戏、升级、暂停、失败、胜利
- `game/world.py` — 关卡、实体管理、碰撞
- `game/entities.py` — 玩家坦克、敌人、子弹、基地、拾取物
- `game/skills.py` — 手榴弹、激光、冷却
- `game/levelgen.py` — 迷宫生成与校验
- `game/pathfinding.py` — A* / 流场
- `game/upgrades.py` — 升级池、抽取、应用
- `game/render.py` — 绘制、辉光、HUD、粒子
- `game/input.py` — 双人键位
- `game/audio.py` — 可选程序化音效
- `tests/` — 纯逻辑测试：生成连通性、寻路、冷却、伤害、升级叠层

实现约定：

- 使用 delta time，移动以像素/秒计算。
- 网格碰撞用 AABB；tile 48。
- 渲染可先画到低分辨率 surface 再放大以统一像素感（可选）。
- 辉光用独立 surface + BLEND_ADD 叠加。

## 9. 数值起点（builder 可调，不是承诺）

- 玩家速度 150 px/s；敌人 60-110 px/s
- 普通弹速 400 px/s，射击间隔 0.35 s
- 手榴弹冷却 6 s，爆炸半径 1.5 tile，对敌伤害 40，自伤/友伤 35%
- 激光冷却 5 s，射程 8 tile，对敌伤害 60，穿透敌人
- 基地 HP 4；玩家无限次复活；重生 3 s
- 普通关 60-120 s；Boss 战 2-3 min

## 10. 留给 builder 的决定

- 具体敌人数值、刷怪节奏、每关波次编排。
- Boss 的弹幕与阶段设计。
- 升级池的具体条目、数值与叠加上限。
- 迷宫生成算法细节、参数与兜底模板。
- 粒子与辉光的具体实现方式。
- 是否加入程序化音效。
- 窗口分辨率与 UI 细节。
- 测试组织与覆盖范围。

## 11. 成功标准

- 两人能在同一键盘完成一局，无需阅读文档。
- 8 关约 20-30 分钟，节奏有明显起伏。
- 每关生成不堵死，基地至少有 3 条可进攻路线。
- 两台坦克的技能使用率都高，且分工明显。
- 基地防守有压力，但不强制一直蹲家。
- 稳定 60 FPS，画面元素可读。

## 13. 评审后的默认决定（builder 的判断，人类可推翻）

- 玩家坦克有 3 点 HP，受击 0.5 秒无敌；护甲升级提高上限或减伤。
- 普通子弹不伤队友、不伤基地；手榴弹误伤队友与自己是 35%，不伤基地；激光穿过队友不伤，且不伤基地。
- 普通子弹可破坏砖墙；手榴弹越过墙体落点爆炸；激光被钢墙挡住、破坏第一格砖墙后停止。
- 基地 HP 每关重置为 4，不跨关累积。
- 关卡生成的「3 条路线」按 30% 格子重合度验收，钢墙为阻挡、砖墙视为可通行。
- 升级选择为同屏先后选择，P1 先、P2 后，无计时。
- 两名玩家每关都参与升级选择。
