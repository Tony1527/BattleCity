# 坦克大战：全息军械库 — 内容扩展与难度设计

- 日期：2026-11-01
- 状态：已批准
- 类型：现有本地同屏双人坦克防守游戏的内容扩展
- 基础规格：`docs/superpowers/specs/2026-10-31-battlecity-design.md`

## 1. 意图与为什么

现有 8 关、双人分工、程序生成迷宫和关间升级已经可玩。这次扩展要解决四个体验问题：

1. **局内变化不够**：地图除了砖/钢墙没有别的地形，敌人压力主要来自数量和血量。加入河流、桥梁、陷阱与拾取物，让走位、分兵和技能时机多一层取舍。
2. **失败惩罚过重**：现在失败会丢掉整局升级，从第 1 关重来。改为失败后重打当前关，保留成长与资源，让玩家把一次失败转化为对同一张地图的第二次尝试。
3. **后期压力曲线单一**：精英只在两关出现。改为每关都有精英，后期数量增加，配合更快的刷怪节奏形成明确升级。
4. **缺少难度与语言选择**：主页加入普通/地狱全局难度和中/英文切换，让新玩家和老玩家都能找到合适入口。

目标仍然是本地同键盘双人合作，一局约 20-35 分钟。不是重做游戏，而是在现有规则上增加可读、可学习、可反制的内容。

## 2. 目标

- 地图上出现三类拾取物：回血、低概率无敌、角色技能强化。
- 失败后可以重打当前关，保留升级、复活次数和基地状态；基地被摧毁时修复满血。
- 地图加入河流、桥梁和 3 秒定身陷阱，全部不可被子弹/激光/手榴弹破坏。
- 提高普通难度的刷怪速度。
- 每关都有精英怪，后期数量更多；精英仍不占普通敌人配额。
- 主页提供普通/地狱全局难度；地狱提高敌人血量、攻击欲望、刷怪速度和基地血量。
- 全部界面支持中/英文实时切换。
- 现有 310 个测试继续通过或被有意更新；新增功能有独立逻辑测试与无头冒烟测试。

## 3. 非目标

- 不做在线联机、手柄、触屏或存档文件。
- 不做每关独立难度选择；难度只在主页全局选择。
- 不新增敌人兵种、Boss 阶段或玩家角色；Boss 只做难度缩放。
- 不做关卡编辑器、地图分享或外部图片素材管线。
- 不做中文配音；音效仍为程序化生成。
- 不保留“失败后从第 1 关重开”的入口；想重开整局必须先退回主页。

## 4. 反目标（即使能跑也算失败）

- 河流把基地或出生点切成无法到达的孤岛，或让关卡只剩一条路线。
- 重打时基地 0 血、复活次数 0 导致一进关就失败。
- 中文界面出现方框、缺字、文字溢出或中英文混排错位。
- 地狱难度只是敌人血更厚，攻击欲望和刷怪节奏没有变化。
- 拾取物可以无限叠加，导致无敌或双激光常驻。
- 陷阱只惩罚玩家、不能反制敌人，或能把 Boss 定身。
- 精英数量增加后变成纯粹的血包堆叠，没有走位和集火取舍。
- 为了新功能破坏现有弹道、寻路、升级或 Boss 的可读性。

## 5. 约束

- Python 3.14，pygame-ce 2.5.x，1280x720，24x13 网格，tile 48。
- 逻辑与渲染分离；纯逻辑可 pytest，无头 SDL dummy 可运行。
- 数值集中在 `config.py` / 小型 dataclass，不散落在渲染或状态机里。
- 关卡生成必须继续满足：至少 3 条从出生点到基地的路线、至少 2 个不同方向的基地入口、出生点安全区。
- 所有新美术仍用 pygame 程序化绘制。唯一外部素材是中文界面字体：使用 OFL 许可的 Noto Sans CJK SC 子集，并附许可证；其余素材自己创作。
- 不引入运行时网络请求；字体和许可证随仓库提交。

## 6. 已选方案（Approaches）

考虑过三种做法：

- **A. 核心内扩展** — 在现有 `World`/`Game` 上增加 `RunState`、`DifficultyProfile`、新 Tile、拾取物和陷阱；地形、寻路、弹道、重试共用一套世界状态。
- **B. 独立子系统 + 事件钩子** — 危险地形、拾取物、难度、本地化各自成系统，`World` 只暴露钩子；重试靠序列化快照。
- **C. 外层战役模式** — 新建 `Campaign` 层管理重试、难度、精英和道具节奏，把现有 `World` 当战斗场景。

**已选 A。** 河流/桥梁本质上是地形规则，重试本质上是整局状态，难度同时影响刷怪、敌人和基地；集中到 `RunState` + `DifficultyProfile` 最不容易出现两套空间或状态真相。B 仍要改核心 Tile 与碰撞，还会引入快照漏字段风险；C 的覆盖层很难与寻路、子弹、激光正确整合，后期大概率重写。

## 7. 整局状态与重试

### 7.1 RunState

新增一个轻量整局状态，由 `Game` 持有；`World` 仍然是单关战斗状态的唯一来源。

```python
@dataclass
class RunState:
    run_seed: int
    difficulty: str          # "normal" | "hell"
    language: str            # "zh" | "en"
    level_index: int
    player_stats: list[PlayerStats]
    upgrade_levels: list[dict[str, int]]
    shared_lives: int
```

- 新开一局：生成新的 `run_seed`，清零等级/升级/复活，难度和语言取主页当前选择。
- 进入下一关：沿用 `run_seed`、难度、语言、`player_stats`、`upgrade_levels`；共享复活次数按现有规则重置为 `SHARED_LIVES + extra_lives`；基地满血。
- 失败重试：沿用 `run_seed`、`level_index`、`player_stats`、`upgrade_levels`、`shared_lives`；用同一关种子重建地图和敌人；玩家以满血、存活状态开始；基地按 7.2 处理。
- 退回主页：丢弃当前 `RunState`；主页保留难度和语言选择。

### 7.2 失败与重试规则

失败条件保持现有两种：

- 基地 HP 归零。
- 两名玩家都被淘汰（共享复活次数已耗尽，且都在当前关出局）。

失败后进入 `gameover` 状态，显示失败原因、当前关卡和剩余敌人数。

- `Enter`：重打当前关。
- `Esc`：退回主页，放弃本局。

重打规则：

- **升级保留**：`PlayerStats` 和 `upgrade_levels` 原样带入。
- **共享复活次数保留**：使用失败时的 `shared_lives`，不重置为 3。
- **玩家状态重置**：两名玩家都以满血、存活、无淘汰状态开始新尝试；即使 `shared_lives == 0` 也如此。这样不会出现“0 复活次数 + 两人出局”一进关就再次失败的死锁。
- **基地状态**：
  - 失败原因是“两名玩家都被淘汰”时，基地保留失败时的当前 HP 和护盾。
  - 失败原因是“基地被摧毁”时，基地修复到满血，护盾按升级重新应用。
- **关卡内容重置**：敌人、Boss、子弹、手榴弹、激光、拾取物、陷阱冷却、粒子全部重建；地图使用同一关种子，所以布局不变。
- 重试不消耗额外资源，也没有次数上限。

### 7.3 关卡推进与胜利

- 普通关的过关条件：普通配额全部刷出并消灭、本关计划的所有精英都已生成并消灭、场上无敌人。普通配额提前清空时，尚未生成的精英立即进入待生成队列，不再等待 22 秒；受“同时最多 2 个精英”限制时，腾出位置后立刻补齐。
- 精英计入 `remaining_enemies`，所以 HUD 不会在精英还没出现时显示 0。
- Boss 关：击败 Boss 即胜利，Boss 关的精英不要求先死；Boss 死亡时清场。
- 通关后进入下一关，共享复活次数按现有规则重置，基地满血。
- 胜利界面 `Enter` 开新局，`Esc` 回主页。

## 8. 难度

### 8.1 主页选择

主页增加两行全局选项：

- `DIFFICULTY: NORMAL / HELL`，用 `Left/Right` 切换。
- `LANGUAGE: 中文 / ENGLISH`，按 `L` 切换。
- `Enter` 进入操作说明，再 `Enter` 开始。

默认：普通难度、中文界面。

难度和语言只影响本局；退回主页后保留上一次选择，但不写入磁盘。

### 8.2 DifficultyProfile

```python
@dataclass(frozen=True)
class DifficultyProfile:
    key: str
    enemy_hp_mult: float
    enemy_fire_interval_mult: float
    enemy_attack_range_mult: float
    spawn_interval_mult: float
    base_hp: int
    boss_hp_mult: float
    boss_interval_mult: float
    elite_hp_mult: float
    elite_shield_mult: float
```

| 项 | 普通 | 地狱 |
|---|---:|---:|
| 敌人最大 HP | x1.0 | x1.5，向上取整 |
| 敌人开火间隔 | x1.0 | x0.8 |
| 敌人攻击距离 | x1.0 | x1.15 |
| 刷怪间隔 | x1.0 | x0.8 |
| 基地 HP | 3 | 6 |
| Boss HP | x1.0 | x1.5，向上取整 |
| Boss 攻击间隔 | x1.0 | x0.85 |
| 精英 HP | x1.0 | x1.5，向上取整 |
| 精英护盾 | x1.0 | x1.5，向上取整 |

- 地狱不提高敌人子弹伤害，避免一次失误直接秒杀。
- 玩家 HP、共享复活、技能冷却和升级池不受难度影响。
- 关卡本身的递进（配额、敌人种类、精英数量）继续存在；地狱是在此之上再乘一层。
- **缩放不叠乘**：普通敌人使用 `enemy_hp_mult`；精英使用自己的 `elite_hp_mult` / `elite_shield_mult`，不再额外乘 `enemy_hp_mult`。精英的开火间隔和攻击距离仍使用 `enemy_fire_interval_mult` / `enemy_attack_range_mult`。精英召唤出的追踪者属于普通敌人，使用 `enemy_hp_mult`。
- `EnemySpec` 在生成敌人时按难度复制并缩放，不修改全局冻结模板。
- Boss 只使用 `boss_hp_mult` 和 `boss_interval_mult`，不受普通敌人/精英乘数影响。
- HUD 的关卡卡片显示当前难度（`NORMAL` / `HELL`）。

## 9. 敌人刷新与精英

### 9.1 刷怪速度

普通难度的基础刷怪间隔整体缩短约 20%：

```python
SPAWN_INTERVAL = (4.8, 4.4, 4.0, 3.6, 3.2, 2.8, 2.4, 0.0)
```

地狱再乘 `0.8`。`MAX_ACTIVE_ENEMIES` 和 `ENEMY_QUOTA` 保持现有表；实际同屏压力由活跃上限和更快的补充速度共同决定。

### 9.2 精英数量

每关都有精英，Boss 关也有 1 个精英与 Boss 同场。

```python
ELITE_COUNTS = (1, 1, 2, 2, 2, 3, 3, 1)  # 索引 0..7，Boss 关为 1
```

- 第一个精英在关卡开始时生成；之后每 22 秒尝试生成下一个，直到达到本关数量。
- 同时存活的精英最多 2 个；达到上限时等待，不跳过数量。等待期间计时器归零后每 2 秒重试一次，而不是重新等 22 秒。
- 普通配额提前清空时，尚未生成的精英立即转为待生成；有空位就生成，不再等 22 秒。过关必须等这些精英全部生成并被消灭。
- 精英是额外压力点，不扣普通敌人配额，但占用活跃槽。普通波次在 `active >= MAX_ACTIVE_ENEMIES` 时暂停，精英可以短暂把数量顶到上限之上。
- 普通关的精英必须全部被消灭才能过关（Boss 关除外，Boss 死亡即胜利）；`remaining_enemies` 计入存活精英和尚未生成的计划精英。

### 9.3 精英缩放

- 基础 HP：`3 + level_index // 2`（第 1 关 3，最终普通关 6）。
- 基础护盾：`12 + level_index`（第 1 关 12，最终普通关 18）。
- 地狱：HP 和护盾再乘 1.5，向上取整；不再乘普通敌人的 `enemy_hp_mult`。
- 召唤：每个精英最多同时保留 1 个召唤物，召唤间隔 10 秒；多个精英的召唤物可以并存。召唤物按普通敌人规则缩放。
- 精英的 0.6 秒前摇、三连散射和护盾再生保留；护盾再生间隔不随难度缩短。
- 精英的移动速度和子弹伤害不随难度变化。

## 10. 地形：河流、桥梁、陷阱

### 10.1 新 Tile

`Tile` 增加：

```python
class Tile(IntEnum):
    EMPTY = 0
    BRICK = 1
    STEEL = 2
    RIVER = 3
    BRIDGE = 4
```

- `RIVER`：坦克不可通过；子弹、激光、手榴弹爆炸不受影响。
- `BRIDGE`：坦克可通过；同样不受子弹、激光、手榴弹影响。
- 砖墙和钢墙规则不变。
- 陷阱不是 Tile，而是放在 `EMPTY` 地面上的静态 `Trap` 实体，这样每张陷阱可以有独立冷却，且天然不阻挡任何弹道。

### 10.2 统一碰撞规则

| 对象 | 玩家/敌人移动 | 子弹 | 激光 | 手榴弹爆炸 |
|---|---|---|---|---|
| EMPTY | 通过 | 通过 | 通过 | 通过 |
| BRICK | 阻挡 | 破坏并停止 | 破坏并停止 | 破坏 |
| STEEL | 阻挡 | 停止 | 停止 | 不破坏 |
| RIVER | 阻挡 | 通过 | 通过 | 通过，不破坏 |
| BRIDGE | 通过 | 通过 | 通过 | 通过，不破坏 |
| TRAP 地面 | 通过 | 通过 | 通过 | 通过，不破坏 |

- `find_path`：钢墙和河流视为不可规划；砖墙仍视为可规划（敌人会打穿），桥梁和陷阱地面可规划。
- `line_of_sight`：只被砖墙和钢墙阻挡；河流、桥梁、陷阱不阻挡视线。
- `compute_laser`：只被砖墙和钢墙截断；河流、桥梁、陷阱不截断。
- 子弹撞墙判定只处理砖墙/钢墙；河流、桥梁、陷阱直接穿过。
- 手榴弹只摧毁砖墙；河流、桥梁、陷阱不进入可破坏集合。

### 10.3 河流与桥梁生成

非 Boss 关生成 1-2 条横向河流带：

```python
RIVER_BANDS = (0, 1, 1, 1, 2, 2, 2, 0)  # 索引 0..7，Boss 关为 0
```

每条河流：

- 占据 1 行，从第 1 列到第 22 列。
- 行号在 4..9 之间选择，避开基地、出生点和基地入口。
- 每条河放置 3 座桥，桥宽 2 格，桥中心在 3..21 之间且彼此至少间隔 4 格。
- 桥格设为 `BRIDGE`，其余河格设为 `RIVER`。
- 河流会覆盖该行原有砖/钢墙；这是有意的，用来形成清晰的横向水带。

多条河流时：

- 两条河的行号至少间隔 2 行。
- 每条河独立选 3 座桥。
- 生成后必须通过 `validate_level`；该校验必须同步升级为河流感知：`RIVER` 阻挡路线，`BRIDGE` 可通过，`STEEL` 阻挡，`BRICK` 仍视为可规划。这样“至少 3 条路线”证明的是桥梁真正连通，而不是忽略河流后的假连通。
- 不通过则换随机种子重试。

兜底地图也包含一条横向河流和 3 座桥，确保兜底仍然可通行。

Boss 关不生成河流，避免干扰 Boss 竞技场；但可以放置陷阱。

### 10.4 陷阱

陷阱是静态地面实体，不进入 `Tile` 枚举。

```python
TRAP_COUNTS = (2, 2, 3, 3, 4, 4, 5, 2)
TRAP_DURATION = 3.0
TRAP_REARM_TIME = 5.0
```

- 放置规则：只放在 `EMPTY`、可被至少一个玩家出生点到达的地面；不放在桥、河、出生安全区、基地 2 格范围内、Boss 竞技场。
- 触发：坦克中心从非陷阱格进入陷阱格，且陷阱已就绪时触发。只在“进入”时触发，坦克停在原地不会反复触发。
- 效果：该坦克 `immobilized = 3.0`，期间不能移动、不能普通射击，也不能使用手榴弹或激光技能；已经发射的子弹/激光继续存在。
- 陷阱触发后进入 5 秒冷却，冷却期间变暗，不触发。
- 冷却结束时，如果坦克仍站在陷阱格上，不会立刻再次触发；它必须先离开该格，再重新进入。
- 影响对象：两名玩家、普通敌人、精英。Boss 免疫。
- 同一张陷阱同一时间只影响第一个触发的坦克；其他坦克在冷却期间可以安全通过。
- 被定身的敌人不会寻路、攻击或召唤；计时结束后恢复。
- 玩家被定身时 HUD 显示 `IMMOBILIZED 2.4` 或类似提示。
- 陷阱不可被子弹、激光、手榴弹破坏。

### 10.5 渲染

- 河流：深蓝青色水面，带缓慢流动的高光线条；与全息风格一致，但不遮挡单位轮廓。
- 桥：钢蓝灰色横向桥面，带护栏和全息边线。
- 陷阱：暗色圆形/方形压力板，就绪时琥珀色脉冲，触发时红色扩散环，冷却时灰暗。
- 河流和桥梁必须与普通地面有明显色差，玩家一眼能判断“能不能走”。

## 11. 拾取物

### 11.1 生成

新增 `Pickup` 实体，放在 `EMPTY` 地面，不阻挡移动和弹道。

```python
ITEM_INITIAL_DELAY = 5.0
ITEM_SPAWN_INTERVAL = (16.0, 22.0)
ITEM_MAX_ON_MAP = 2
ITEM_TTL = 25.0
ITEM_WEIGHTS = {"repair": 74, "stim": 25, "invincible": 1}
```

- 关卡开始 5 秒后尝试生成第一个；之后每 16-22 秒尝试一次。
- 场上最多 2 个；达到上限时暂停生成。
- 每个拾取物存在 25 秒，最后 5 秒闪烁提示。
- 生成位置：`EMPTY`、不被单位/基地/陷阱占用、从至少一个玩家出生点可达、避开河流/桥/出生安全区。
- 敌人、Boss、子弹、激光、手榴弹都不与拾取物交互。

### 11.2 修复包（repair）

- 外观：绿色十字/医疗包。
- 拾取者恢复 1 点 HP，不超过最大 HP。
- 如果拾取者满血，拾取物不被消耗，留在原地，让另一名玩家有机会拾取。
- 修复包是最常见的拾取物（74%）。

### 11.3 技能强化（stim）

- 外观：青蓝色旋转菱形/药剂瓶，带角色色边。
- 拾取者获得 20 秒技能强化；重复拾取只刷新到 20 秒，不叠加。
- P1：手榴弹爆炸半径翻倍（`grenade_radius * 2`），分裂手榴弹同样受益。
- P2：激光变成两束平行光束。
- 强化期间 HUD 显示 `STIM 12.4` 和角色专属标记（P1 `R2`，P2 `2X`）。
- 技能强化不改变冷却、伤害或射程。

**双激光规则：**

- 两束光从玩家中心沿垂直方向各偏移 14 px，方向与玩家朝向一致。
- 每束造成 `max(1, round(laser_damage * 0.6))` 伤害。
- 同一敌人或 Boss 在一次双激光中最多被一束命中，避免双倍结算；Boss 也只结算一次。
- 两束可以分别命中不同敌人。
- 两束都基于开火前的同一份网格快照计算第一条砖墙；如果两束命中同一块砖，只摧毁一次，两束都停在该砖前。不会出现“第一束打穿后第二束穿过去”的连锁。
- 两束都加入现有 `world.lasers`，渲染和生命周期规则不变。

### 11.4 无敌（invincible）

- 外观：金色星形/护盾药剂，明显比另外两种更亮。
- 只在拾取物生成时以 1% 权重出现，是真正的低概率道具。
- 拾取者获得 6 秒无敌；期间免疫玩家子弹、敌人子弹、爆炸和 Boss 激光伤害。
- 不叠加；重复拾取刷新到 6 秒。
- HUD 显示 `INV 4.2`，玩家周围有金色脉冲光环。
- 无敌不免疫陷阱定身；陷阱仍然会触发。

### 11.5 HUD

- 每个玩家卡片底部增加一行状态标记，最多显示两个：
  - P1 强化：`R2 12.4`
  - P2 强化：`2X 12.4`
  - 无敌：`INV 4.2`
  - 定身：`HOLD 2.1`
- 没有状态时不显示，保持 HUD 干净。
- 拾取时播放短促程序化音效并产生小型粒子爆发。

### 14.2 关键接口

- `Game.__init__(..., difficulty="normal", language="zh")`：测试可直接构造。
- `Game._retry_level()`：用当前 `RunState` 重建当前关；失败原因是基地摧毁时修复基地。
- `World(..., difficulty: DifficultyProfile, shared_lives: int | None = None, base_hp: int | None = None, base_shield: int | None = None)`：`base_hp` 是当前 HP（`None` 表示满血），最大 HP 仍由难度决定；`base_shield` 是当前护盾（`None` 表示按升级重新应用）。这样重试可以精确恢复“玩家全灭但基地未毁”时的基地状态。
- `World.traps: list[Trap]`、`World.pickups: list[Pickup]`。
- `Player.immobilized: float`、`Player.stim_timer: float`、`Player.invincible_timer: float`。
- `Enemy.immobilized: float`；`Boss` 不读取该字段。
- `World.difficulty: DifficultyProfile`，供 HUD 和缩放逻辑读取。

## 17. 风险与取舍

- **Tile 语义扩散**：河流/桥会同时影响移动、寻路、子弹、激光、手榴弹、生成校验。用一张统一碰撞表 + 针对性测试锁住行为，避免各模块各自判断。
- **重试状态重复**：不让 `World` 自己保存整局状态；`Game`/`RunState` 负责，`World` 只接收构造参数。
- **中文字体体积**：使用子集字体，提交许可证；运行时不依赖 fonttools。
- **地狱平衡**：先按表中乘数实现，再用无头模拟和手工试玩调参；数值集中在 `DifficultyProfile` 和 `config.py`，便于改。
- **精英堆叠**：同时最多 2 个、每个最多 1 个召唤物，避免后期变成无法处理的怪海。
- **无敌过强**：6 秒、1% 权重、不可叠加；仍然会被陷阱定身。
- **双激光过强**：每束 60% 伤害，同一目标一次只吃一束，避免对 Boss 双倍结算。

## 20. 评审后的默认裁定（builder 的判断，人类可推翻）

以下问题来自独立 builder 评审，均已在正文中落为明确规则：

1. **Boss 关的精英不阻塞胜利**：Boss 死亡即胜利并清场；Boss 关精英是额外压力，不要求先击杀。
2. **普通关不会因提前清完配额而漏掉精英**：配额清空时，尚未生成的计划精英立即进入待生成队列；过关必须等它们全部生成并消灭。同时最多 2 个精英，腾出位置后立即补齐，不再等 22 秒。
3. **难度乘数不叠乘**：普通敌人吃 `enemy_hp_mult`；精英只吃自己的 `elite_hp_mult` / `elite_shield_mult`；Boss 只吃 `boss_hp_mult` / `boss_interval_mult`；召唤物按普通敌人缩放。
4. **路线校验必须河流感知**：`RIVER` 阻挡、`BRIDGE` 可通过、`STEEL` 阻挡、`BRICK` 可规划；“至少 3 条路线”必须证明桥梁连通。
5. **基地重试参数分开**：`base_hp` 是当前 HP，`base_shield` 是当前护盾；最大 HP 由难度决定。玩家全灭重试保留当前基地 HP/护盾，基地被毁重试恢复满血。
6. **定身封锁全部行动**：不能移动、不能普通射击、不能使用手榴弹或激光；已有弹道继续。
7. **陷阱只在“进入”时触发**：站在陷阱上不会在 5 秒后再次被定身；必须先离开再进入。
8. **双激光按开火前网格结算**：两束各停在自己的第一块砖前；命中同一块砖只摧毁一次；同一目标（含 Boss）一次双激光只结算一束伤害。
